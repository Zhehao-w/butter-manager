# butter-manager

Windows 本地轻量游戏库与启动器，基于 Tauri / Rust / React / SQLite。当前版本 **0.3.0**，采用 [MIT 许可](LICENSE)。当前流程以本文和 [v0.3 实施说明](docs/v0.3-implementation.md) 为准。

Lightweight Windows game library manager with local importing, version tracking, save management, and MTool/QSP launcher support.

目前按源码构建运行，0.3 发布准备和已知边界见 [变更记录](CHANGELOG.md)。程序仅支持 Windows，主要开发与验证环境为 Windows 11。

## 游戏库与启动

- 列表和卡片均可直接启动，点击游戏打开详情。支持直接 EXE、Windows 默认应用、本地 QSP 播放器和公共 MTool，启动方式使用不同颜色标签。
- 游戏状态为从未玩过、正在玩、已通关。成功启动后标记正在玩，已通关状态保留；可在详情手动修改。
- 支持状态、引擎、启动方式组合筛选，以及名称、别名、路径搜索和需处理筛选。视图及各页面排序在本机保存，搜索和筛选只保留本次会话。
- 目录检查只检查目录和启动文件，不遍历资源树、不自动移除记录。新游戏需选择扫描候选再登记；扫描不覆盖已有名称、版本和历史。
- 扫描和检查使用悬浮进度横幅，不挤压列表。完成或取消后停留 5 秒，再先渐隐 300ms、后收起位置 300ms；悬停或聚焦时暂停倒计时，失败提示保留至手动关闭。扫描横幅提供“查看扫描结果”。
- 窗口按鼠标所在屏幕的可用区域居中；不可获取时退回主屏幕。侧栏顶部显示应用图标与署名 by Zhehao-w，并以细线分隔导航；选中导航保持统一字重，通过浅蓝背景、图标颜色与药丸竖线强调。设置位于插画下方，版本号显示在入口右侧；应用图标、介绍与许可位于设置页最下方，无独立关于页面。

## 导入与更新

1. 进入“导入”，点击“添加文件夹”，可选择多个游戏或合集。自动判断整包或下级游戏，范围不明确时先选择范围。发现阶段过滤点号开头、Hidden / System、系统目录和链接；已选整包仍保留资源和内部存档。
2. 在“新的导入”中搜索、勾选并修正版本、引擎、启动文件或目标名称。按名称、目录名和别名推荐已有游戏；唯一完整名称匹配可自动关联但不自动勾选，弱关联或多候选需人工选择。可手动关联或“改为新游戏”，不自动比较版本大小。
3. 更新选择“保留旧存档”（默认）或“使用新包存档”，无需额外勾选确认。已关联且明确版本相同的副本，可通过“删除导入副本…”单独确认后回收，库内游戏不变。
4. 点击“生成导入与更新计划”，在“待确认”查看来源、目标、版本、存档处理及冲突，执行前保留一次总确认；有冲突时返回调整。
5. 同盘优先移动目录；跨盘复制一份新包，核对相对路径、类型、数量和大小，登记提交后清理来源。**不读取全部游戏资源进行内容指纹或字节比对**，不保留第二份完整游戏包。
6. 更新保留原 UUID、名称、别名、状态、入库时间、存档位置和运行历史，替换版本与启动配置。成功后旧版本进入 Windows 回收站，清理本次暂存及存档临时副本，不长期保留旧版本。

进度在选定目录后才出现，显示阶段、当前游戏/文件及可用的传输进度、速度和剩余时间。准备和运行状态检查使用连续滑动条。新操作只检查运行进程，不逐个预检全部资源占用；实际文件操作失败会停止并保留恢复状态。

中断后到“待确认”继续或撤回未完成项，成功项保留。提交前失败恢复原安装位置，提交后继续来源清理、回收与临时清理。新旧操作记录分别沿用对应恢复规则。

“导入记录”按游戏展示成功项及已回退项，按日期分组、最新在前，搜索覆盖全部记录。“查看游戏”打开库内详情，“详情”展示路径、存档处理和可用回退入口。新记录保存完成时间；旧记录注明按记录文件时间显示。

## 存档与回退

扫描、分析和导入共用 [存档识别字典](docs/save-detection.md)，只添加实际存在的常规路径，手动配置优先。RPG Maker 常见 save、www/save；Ren’Py 存在 game/saves 时以它为准；其他路径通过明确配置或元数据识别，可在详情补充。

- **保留旧存档**：只处理已配置的游戏内部存档，覆盖到新版相同相对位置；保留必要的存档复制校验。
- **使用新包存档**：不迁移内部旧存档，旧存档随旧版进入回收站。
- **外部存档**：更新和回退均不操作 AppData 等游戏目录外存档，不创建其副本。
- **回退**：仅恢复回收站中仍存在的原旧版，从最近更新开始；当前内部存档带回旧版，换出的版本进入回收站。清空回收站或手动恢复旧版后无法回退。

不转换存档格式，也不推断新旧版本目录布局变化；游戏自身的存档兼容性需实际读档确认。管理器文件不写入游戏或存档目录。更新需要临时空间，中断文件在完成或撤回后清理。

## 删除与目录维护

“关联新目录”修复外部改名或移动后的记录。“从库中移除”只移除记录，不操作文件。

“删除游戏文件（回收站）”同时回收整个游戏目录和已关联存档，包含外部关联存档，没有保留选项；执行前单独预览确认。保护系统目录、库根目录、管理器、公共工具、其他游戏和共享存档。删除导入副本只回收来源及其内部存档。

回收站不可用时不改为永久删除。文件回收和数据库无法成为单一事务，部分失败保留记录并说明已完成操作。设置中的“清空库”需要明确输入确认，只清空库记录与设置，游戏文件保持原位。

## 本地开发

需要 Windows C++ Build Tools（桌面 C++ 工作负载及 Windows SDK）、WebView2、Node.js / pnpm 和 Rust MSVC 工具链。系统依赖安装方法见 [Tauri 官方 Windows 环境说明](https://v2.tauri.app/start/prerequisites/#windows)。

开发与自动检查使用 `.node-version` 中的 Node.js 24.19.0、`package.json` 指定的 pnpm 11.25.0、`rust-toolchain.toml` 中的 Rust 1.99.0；依赖版本由两个锁文件固定。

```powershell
git clone https://github.com/Zhehao-w/butter-manager.git
Set-Location butter-manager
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm tauri dev
```

安装 Rust 时使用 MSVC 默认主机。已有项目本地工具链的开发者可先执行 `. ./scripts/Use-Toolchain.ps1`；新环境直接使用已安装的系统工具链，无需复制 `.tools`。

```powershell
pnpm tauri build --no-bundle -- --locked
```

程序位于 `src-tauri/target/release/butter-manager.exe`。仅打开 Vite 浏览器页不能访问本地数据库、扫描或启动游戏。常用检查为 `pnpm format:check`、`pnpm test:ui`、`pnpm build`、`pnpm test`、`pnpm check`；具体 Windows 自动检查和贡献约定见 [CONTRIBUTING](CONTRIBUTING.md)。CI 不上传产物或自动发布 Release。

开发和覆盖升级不备份正式数据库、WAL、SHM，不导出可恢复记录；升级可只读核对数量、完整性和旧列不可恢复摘要。测试使用独立临时夹具，不操作真实游戏。数据库、导入恢复记录、依赖缓存及构建产物不提交仓库。
