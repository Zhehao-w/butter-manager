# 图标与侧栏立绘

设置页的“外观”支持独立选择原版或新版应用图标、侧栏立绘，选择后立即保存，重启恢复。顶部品牌、设置页关于区和原生窗口图标使用同一选择。

新版图片来自用户提供的透明 PNG，仅做图标尺寸和格式转换；新版图标采用 2026-10-08 最后提供的图二版本。侧栏立绘采用 60% 不透明度和 0.2px 的轻微显示平滑，减少低透明度造成的发白及缩放后的细碎边缘；原 PNG 不改写。顶部不渐隐，底部从 92% 渐隐，并填满侧栏裁切显示；立绘与导航之间留白为 30px，较原位置下移 12px。设置页立绘预览沿用同样显示样式。默认使用新版。

外观设置保存在应用本地数据目录的 `appearance.json`，独立于游戏数据库。清空游戏库不会重置外观。保存失败时保留原选择并显示错误；格式错误不会在启动时静默覆盖文件。

## 当前文件图标

按用户同意的阶段方案，EXE 的嵌入文件图标固定为新版。设置中的切换影响应用内及运行窗口图标，暂不改变磁盘上的 EXE 图标。新版构建包含新版 PNG/ICO；Windows 资源管理器可能仍缓存之前的文件图标。

## 后续文件图标同步方案（尚未实现）

Windows 的 EXE 文件图标是可执行文件资源；窗口图标切换不会改写它。后续先明确要同步实际 EXE 文件还是桌面/开始菜单入口，再选择实现：

1. 桌面和开始菜单快捷方式可引用选择对应的 ICO，不需要重写应用文件。该方案适合入口图标切换，但不能替代实际 EXE 文件图标切换。
2. 如果需要实际 EXE 图标同步，加入独立更新助手：关闭应用后生成带选定资源的新文件，检查其可执行性，再替换和重启。覆盖失败必须保留原 EXE 并提示原因，不能直接修改正在运行的应用文件。
3. 上述方案需验证安装目录权限、Windows 图标缓存、多实例、失败恢复及未来代码签名；修改已签名 EXE 会破坏签名，签名版本宜使用分别签名的构建或快捷方式方案。

当前阶段不引入自修改 EXE、权限提升或后台替换助手，也不操作游戏文件及数据库副本。
