# 2026-10-17 全量审查处理决定

> 历史记录：2026-10-25 用户已明确改为发现随包 MTool 后默认勾选清理整个一级目录，移除白名单及清理专属依赖资格检查；以下是当时的审查决定。当前规则见 [随包 MTool 清理](import-mtool-cleanup.md)。


审查基线：main `8cc4c3560eae2e046c63b260ed7b5785f3e14254`，应用版本 1.2.0。以下状态按用户对三项审查结果的后续决定记录。

## 第 1 项：跨游戏存档路径检查，已接受

随包 MTool 清理检查当前游戏的关联存档、公共 MTool 及其他游戏安装目录，但不检查其他游戏记录所关联的存档路径。若另一游戏明确把存档放在待清理工具目录中，工具目录整体回收时也会带走这些文件。

用户已明确接受这一现有边界。本项不安排修复，后续审查不再把相同行为列为 issue。该决定不改变包装目录白名单、当前游戏存档保护、公共工具保护或目录身份检查。

## 第 2 项：确认后的包装目录变化，已接受

初次检测会用既有白名单检查一级包装目录。实际清理时只复核已记录的目录身份和关键文件，没有重新检查一级目录成员。

例：生成计划时，目录只有 `辅助工具/client/`，符合工具包布局；随后用户在 `辅助工具/` 下添加 `个人文件/进度.sav`。重新检测会拒绝这一混合包装目录，但使用已生成计划执行清理时，原有锚点仍一致，整个 `辅助工具/` 仍可能被送入回收站，新增文件也会被带走。清理失败后隔一段时间重试同样可能遇到此情况。

用户明确决定不重新检查，存档不应放在 MTool 目录内。本项接受现有行为，不安排清理或重试前重新枚举包装目录成员；后续审查不再把相同行为列为 issue。初次识别的包装目录白名单及现有锚点、目录身份和其他保护继续保留。

## 第 3 项：单文件存档的跨盘更新，修复纳入 1.2.1

旧游戏关联单个存档文件，新版本也携带同名文件，且跨盘更新选择保留存档时，来源文件恰好等于存档路径。原实现在归档路径后拼接空后缀，产生类似 `bundled-saves/0/` 的路径，导致对普通文件的检查失败。版本已提交但任务卡在 `update_cleanup`，继续和撤回会重复失败。

实施范围：

1. 修正 `src-tauri/src/updater.rs` 的 `remove_source_basic`：空后缀直接对应归档文件；目录内文件仍按相对后缀定位。
2. 用隔离临时夹具覆盖：单文件存档且新包有同名样例、已提交更新在清理阶段恢复继续、通过撤回入口完成已提交更新的剩余清理，以及原有目录存档和新包未携带该文件的情况。核对旧存档内容、来源清理、任务状态及重试幂等性。
3. 保留既有 Journal、目录身份、任务互斥和来源删除保护；运行标准 Linux 完整检查，交付前完成 Windows CI 原生测试、严格 Clippy 与 EXE 构建。

已修正空后缀处理，新增两项回归覆盖上述正常完成、重启继续与撤回场景。新增用例在旧实现上均以 `NotADirectory` 失败，修复后通过。保留现有目录存档处理及全部文件保护。完整检查结果见 [验证记录](validation.md)；修复 PR #7 已合并，Linux / Windows CI 与 EXE 构建通过（运行 39032483896）。修复纳入 1.2.1，正式发布状态以对应 Release 为准。
