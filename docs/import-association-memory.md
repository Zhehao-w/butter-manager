# 导入关联记忆

本功能首次随 1.2.0 交付；当前版本为 1.3.1，提供 Portable ZIP 与同名 `.zip.sha256` 文件。PR / main 的开发 EXE 通过对应 CI artifact 交付。

**1.3.1 起默认勾选「记住关联」并使用紧凑布局**；1.3.0 及更早版本默认不勾选。

## 使用方式

例如库里已有「月光庭院」，新下载包叫 `Moonlight Garden v0.8 汉化版`，需要手动关联一次：

1. 在导入的「游戏关联」中选择已有游戏。
2. 关联区标题行右侧的「记住关联」默认勾选，可取消。悬停可查看保存时机与用途；切换到另一款游戏时重新默认勾选，改为新游戏时清除该选择。原有唯一精确匹配预选也采用此默认值。
3. 生成计划、确认更新；只有版本数据库事务提交成功才保存记忆。
4. 下次导入 `Moonlight Garden v0.9 汉化版` 时优先推荐原游戏，显示「曾由你确认关联」。仍需点击关联，再进入原有计划确认流程。

游戏详情 → 基础信息 →「导入关联记忆」可查看来源名称、识别依据与确认时间，并逐条忘记。忘记不修改游戏文件、资料或别名；正常名称匹配仍可能推荐同一游戏。当前任务或未完成文件操作可能阻止忘记，结束后可重试。

记忆绑定 UUID，正常改名、版本更新和整库路径迁移不改变它。不自动追加名称别名、不从历史导入或查重确认中自动学习。每次更新只在保留勾选且提交成功时保存；同一游戏的相同特征更新确认时间，不按每个版本重复新增。来源名称过于通用或信息不足时，预览会要求取消记住；仍可正常手动关联更新。

## 推荐边界

- 记忆标题特征保持 v1 格式兼容，不重写或回填历史记忆；已识别的版本及包装标记按该格式处理，保留数字、季数、章节、续作、外传和版本类型差异。普通推荐可独立改进，命中记忆仍要检查当前作品标记冲突。
- 1.3.1 的普通名称推荐识别完整、分离的「官中无修版」等包描述；`Demon` 不再误作 `Demo`，明确的 Demo / Remake / Remastered 仍保留作品类型保护，包括版本号后的 Demo 标记。
- 1.3.1 的 Import 弱推荐允许完整中英标题一致、且只有末尾三至四位零开头数字不同或缺失的旧包名。例如「断角魔王艾莉丝的重生谭 The Rebirth Tale of Broken Horn Demon Lord Alice 072」可推荐给同完整标题的「官中无修版」或 `073` 包，理由明确指出末尾数字需确认。这不是版本解析，不自动关联；普通数字、其他标题数字、不同译名、章节、DLC 或试玩标记冲突不会使用此放宽。库内查重及记忆数字保护不使用此规则。
- 已确认的来源标题特征可独立召回原 UUID。完全换译名或后来改为 `Game v0.9` 等通用包名时，仍会检查已保存且本次存在的有效静态项目标识；缺少共同特征时仍需手动关联。通用包名本身不能建立新记忆或独立召回游戏。
- 静态标识只复用 Ren’Py 的明确配置、Unity `app.info` 的 company / product、Godot 项目名，拒绝通用模板值。只读、有大小上限、拒绝链接；不读取存档或全盘哈希。
- 特色 EXE、外部存档等既有证据继续参与普通名称推荐，但不会单独成为新的记忆身份。`Game.exe`、`<GAME>/save` 和同引擎不足以跨译名推荐。
- 相同特征对应多个 UUID 时保留各自决定，显示候选冲突，不覆盖或合并游戏。当前目标记录与来源存在明确作品标记冲突时不使用记忆推荐。
- 新增记忆推荐始终需要确认；与其他普通候选冲突时取消自动预选。没有记忆命中时保留原有唯一精确匹配的预选。自动预选本身也不会执行文件操作。
- 候选按 UUID 去重，最多五项；记忆之间不推导传递关系。库内查重继续使用原有更保守的规则，不使用导入记忆。

## 数据、失败与恢复

schema 11 → 12 创建空的 `import_memories` 表，保存目标 UUID、来源标题、版本化标题特征和有限静态标识、确认时间；不修改旧别名、游戏或查重记录。升级不备份正式数据库、WAL、SHM，不导出可恢复记录。

**schema 12 不能由旧版 1.1.0 打开。** 游戏版本回退仍可使用现有流程，但不等同于把管理器 EXE 降级。开发和自动化验证只使用隔离临时资料。

| 情况                       | 行为                                                                      |
| -------------------------- | ------------------------------------------------------------------------- |
| 仅点选、生成预览或放弃预览 | 不写记忆                                                                  |
| 提交前失败、取消或撤回     | 不写记忆                                                                  |
| 版本提交成功               | 在同一数据库事务内保存勾选的记忆；记忆写入失败也回滚该事务                |
| 数据库已提交，后续清理失败 | 保留记忆，文件任务仍需继续或处理                                          |
| 重试 / 中断恢复            | 复用版本 operation 的幂等提交，不重复学习；已忘记的记忆不从已提交任务重建 |
| 游戏版本回退               | 保留人工身份判断，不据此承诺存档或版本兼容                                |
| 删除游戏 / 清空库          | 清理对应记忆                                                              |
| 旧 Journal                 | 缺少新字段时默认不记住，启动时不回填历史                                  |

前端只提交是否记住；标题和特征由后端从当前分析来源生成，随计划保存。不将用户输入的目标显示名当作来源证据。生成计划的后端也重新检查记忆候选，不能只绕过前端就把待确认推荐当作新游戏导入；明确「改为新游戏」继续可用。

## 验收

自动化使用合成名称、项目配置、临时数据库和目录，覆盖跨版本及译名召回、多目标冲突、模板标识反例、事务失败、恢复重试、忘记、防止旧任务重建、迁移、删除及清空；保留全部 Import / Journal / 回退 / 路径与存档保护测试。

Windows 实机重点验收：第一次明确记住 → 更新完成 → 重启 → 导入新版 → 正确推荐且仍需确认 → 查看 / 忘记。再核对长名称、窄窗口、高 DPI、未完成任务提示和已有别名保持。Linux 自动化不替代这些项目。
