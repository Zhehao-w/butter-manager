# Import 随包 MTool 清理

清理集成在现有 Import 卡片、计划预览与导入记录中，不增加导航或数据库表。以下整目录选择调整尚未发布，应用版本仍为 1.5.2、schema 15。

## 选择与执行

- 发现随包 MTool 后，默认勾选「导入成功后清理随包 MTool」；取消即保留。摘要显示「回收清理 / 保留」，设置中列出具体路径。
- 清理单位始终是包含工具的整个一级目录。比如发现 `MTool/Tool/MTool.exe`，回收的是整个 `MTool/`，包含其中全部文件、未知兄弟目录、工具记录、备份和运行时。
- 不设内容白名单，不要求 package.json 包名或注入器齐全，不因夹杂游戏资源、链接或启动 / 存档依赖而将已发现的工具标为保留。清理不会强制切换启动方式，也不要求配置公共 MTool。使用公共工具的启动选项单独设置，仍按其正常启动规则验证。
- 游戏已入库、来源清理和更新改名完成后，所选一级目录及关联根目录 BAT 移入 Windows 回收站，不执行 BAT。普通根目录脚本和目录外文件不纳入。
- 回收失败时游戏仍在库中，导入记录显示路径、原因与重试入口。

取消只改变清理选择，不改变启动配置；再次勾选也不覆盖启动方式。重新分析保留本次用户选择。已有计划按原记录执行，不给历史未勾选任务自动开启清理。

## 有界识别

优先静态读取根目录中英文 MTool 启动 BAT，引用不能识别时反向查找一级目录或再嵌套一层的 `MTool.exe`，目录名称不固定。搜索有界，不递归遍历游戏资源，不执行脚本。仅有名字为 MTool 的目录、翻译说明或翻译 JSON 不构成随包工具。

关联启动 BAT 仍需符合已支持的静态格式和当前目录归属；打包机器的旧绝对路径仅在旧目录不存在、静态配方明确且本地对应工具唯一时关联。这里判断 BAT 的归属，不决定已找到目录能否清理。固定配套移除脚本 `从游戏中移除工具文件.bat`、`Remove Tool files from game.bat` 随目标回收，绝不执行。

## 记录与恢复

新清理记录仅保存所选一级目录身份；不再读取包清单、检查注入器或列举目录内容以决定清理资格。目录内容变化不会取消整目录回收。关联 BAT 继续使用有界小文件摘要，确认回收的是已选脚本。

沿用 Import Journal、当前游戏目录归属、目标与库根目录身份检查。复制后绑定目标身份，记录「回收中」后调用现有回收站接口。所选路径被替换时不会回收替换后的对象；回收后中断可确认已有回收站条目，避免重复操作。旧 Journal 兼容原有关键文件锚点，继续复核已记录内容，不迁移或补选清理。

上述检查只确保处理的是用户所选位置和对象；不按目录内容增设清理资格。普通 Import 的路径、链接、运行任务及文件传输保护仍由原流程负责，本次不修改。更新与版本回退沿用原流程，回退不触发旧版工具清理。

## 手动验收

1. 添加含一级 / 二层随包 MTool 的游戏，确认默认勾选、摘要及一级路径正确；夹杂未知组件也保持可清理。不带 package.json / injector 的工具仍可识别。
2. 取消勾选后导入，整个工具目录及关联脚本保留；重新分析不重置选择。
3. 勾选后导入，整个一级目录进入回收站；普通根目录脚本、游戏目录外文件保持。分别验证移动及跨卷复制。
4. 未配置公共 MTool 时选择直接启动，清理仍可执行；清理勾选不改变启动方式。公共 MTool 需由用户另行设置。
5. 工具被占用时确认失败原因与重试；清理阶段中断后继续，不重复回收，不回收占用旧路径的新对象。
6. 保留旧存档进行更新，再回退，确认原游戏记录、存档、版本及启动配置恢复。

自动测试仅使用隔离合成目录和数据库。Windows 原生回收站行为与真实游戏验收由 Windows CI 及用户完成，不以 Linux 核心测试替代。
