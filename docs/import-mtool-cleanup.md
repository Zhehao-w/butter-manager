# v0.4 · Import 随包 MTool 清理

本地开发功能，尚未发布。集成现有导入选择、计划预览与导入记录，不增加导航或 SQLite 表。

## 使用

- 优先检查游戏根目录的 `与工具一同启动.bat`、`StartWithTool.bat`，兼容旧的带空格 / 下划线英文名称。仅静态读取，不执行 BAT。
- 没有可识别 BAT 时，检查一级目录或再嵌套一层的 `MTool.exe`；目录名称不固定。
- 同时纳入根目录固定名称的配套移除脚本：`从游戏中移除工具文件.bat`、`Remove Tool files from game.bat`。它们只作为待回收文件，绝不执行；多个工具包中存在归属不明内容时保留这些脚本。
- 预览显示整个一级工具目录和关联根目录 BAT。可确认的工具包默认勾选“导入成功后清理随包 MTool”；不能确认的目录只展示原因并保留。
- 勾选清理后，无论新游戏还是版本更新，都使用公共 MTool 启动。游戏 EXE、工作目录、公共工具与 loader 必须可用；相关配置不满足时计划阻止执行，取消清理或调整配置后重新生成计划。
- 游戏已入库、来源清理和更新改名完成后，确认的目录与 BAT 移入 Windows 回收站。失败时游戏保留，导入记录显示未清理内容、原因与重试入口。

## 识别与速度边界

BAT 能明确引用工具路径时直接检查该目录；没有可识别引用时才枚举根目录及两层工具候选路径，二层枚举合计至多 4096 项，不递归搜索游戏资源。工具目录需要 MTool 包名与注入器等相互印证，启动 BAT 需要确认静态工具路径；两个固定名称的移除脚本按配套文件处理。已知运行时 / loader 使用窄范围清单；其他包内资源只有与已配置公共 MTool 的对应文件内容一致时才能确认。工具版本不同或未知内容将保留。

工具包内混入游戏资源、非空游戏库 / 存档备份、链接或未知文件时不清理；一级包装目录只能包含已确认的工具包。单个检查限制 4096 项、512 MiB，根目录 BAT 至多 128 项、每个至多 256 KiB。超过边界时保留，不做空间统计。程序从不修改公共 MTool。

## 恢复

清理沿用 Import Journal，记录相对目标、文件身份 / 元数据及小型 BAT / 包清单摘要。复制后核对目标内容并绑定目标文件身份，再记录“回收中”后调用现有回收站代码。

回收后中断：继续任务时按已记录身份确认回收站条目，跳过已回收目标。旧路径被新文件占用时不会删除新内容。正常回收失败不改变游戏成功状态；可以在导入记录中排除原因后重试。回退仍恢复原旧版与当前内部存档，不在回退时清理旧版工具。

## 手动验收

本轮添加了隔离回归用例，未执行测试或构建 EXE，也未操作 GUI、真实游戏文件或正式数据库。已完成格式检查、TypeScript 类型检查、Rust 类型检查及全目标 Clippy 静态检查。

1. 用中文 / 英文 BAT、不同目录名，分别尝试一级 MTool 和二层包装；预览路径正确，默认勾选，取消后文件保持。
2. 不放 BAT，只保留完整工具包；可反向识别。加入未知文件、游戏资源或存档备份后，应显示保留原因。
3. 新游戏导入与旧版更新后，工具和关联 BAT 进入回收站，普通 BAT / 游戏资源 / 公共工具保持；库内启动方式为 MTool，启动目标是实际游戏 EXE。
4. 未配置公共工具、loader 缺失，或启动文件 / 工作目录指向待清理目录时，计划阻止执行；修正后可重新生成。
5. 保留旧存档的更新及版本回退，确认进度、存档、名称、运行记录与原流程一致。
6. 让工具文件暂时无法回收，确认游戏仍在库内且可用，导入记录显示未清理路径和原因；解除占用后重试。
7. 清理阶段中断后重新打开管理器并继续，确认已回收内容不重复回收、新占用旧路径的内容保留。
