# 直接 EXE 启动参数（开发构建，未发布）

本功能增加游戏详情与 Import 的「启动参数」，只用于直接启动 EXE。启动文件仍单独选择，例如 `trainPJ.exe`；参数框填写 `-dx11`，不要把它拼进文件名。应用版本暂为 1.3.4，功能状态以构建提交为准，不代表正式 v1.3.4 已包含本功能。

## 使用

- 详情 → 启动配置：输入参数，点击「保存资料」。游戏库启动读取保存配置；详情中的临时启动使用当前草稿，不自动保存。清空参数并保存即可恢复无参数启动。
- Import → 启动配置：新游戏默认无参数；关联已有游戏后默认继承旧参数。可覆盖、明确清空，或通过「恢复继承旧配置」撤销覆盖。切换关联目标后重新继承新目标配置。
- Import 卡片顶部在实际使用参数时显示「含启动参数」，悬停可查看内容；清空或改用 MTool / QSP / 文档后不显示。待确认计划按该计划的参数快照显示，避免受库中后续修改影响。
- 多个参数以空格或 Tab 分隔；双引号包裹含空格参数，例如 `--profile "Profile One"`。空引号 `""` 表示空字符串参数。实际参数及效果由游戏决定。
- 采用 Windows 风格的反斜杠 / 双引号规则：`\"` 表示字面双引号，结束引号前的反斜杠需成对；例如 `--path "C:\Game Saves\\"`。单引号是普通字符，不作为分组引号。
- 不完整双引号会明确提示，保存和生成计划前校验；后端在持久化、计划与启动入口再次验证。拒绝换行、NUL 及其他控制字符。

## 范围与保护

直接 EXE 通过 `Command::args` 接收独立参数，不经过 cmd、PowerShell、BAT 或其他 shell；不做环境变量、通配符或命令替换。`&`、`>`、`%PATH%` 等是普通参数内容。

MTool、外部播放器和 Windows 默认应用打开文档均不接收此参数字段；只有直接 EXE 模式显示参数输入。切换启动方式隐藏输入并保留参数文本，切回直接 EXE 后继续使用。重新分析启动配置不覆盖用户参数；扫描、目录关联、改名与整库路径迁移不会从包内推断或改写参数。详情中的公共 MTool 路径与 Loader 排在高级启动选项上方，沿用普通表单排版。

不会读取下载包快捷方式或 BAT 来获取参数，也不会按引擎自动加 `-dx11`。现有 MTool BAT 标记 / 启动目标识别规则保持。

详情中的启动文件保持普通文本输入，可浏览选择；分析发现的 EXE 在「分析结果」中列出，可点击选用。「填入推荐配置」将推荐启动配置填入当前草稿，保留参数及未保存保护，不自动保存。工作目录、脚本分析和调试预览集中在最下方的「高级启动选项」。基础信息的标准名称用于识别和关联，不等于文件夹名称；修改目录名使用「记录与管理 → 目录与库记录 → 重命名目录」。

## 数据、更新与恢复

schema 13 → 14 在事务中添加空字符串默认字段，不改变原记录资料、UUID、存档或运行历史。旧数据库可升级，清空库后也使用 schema 14；不备份正式数据库、WAL、SHM 或导出可恢复记录。**已发布的 v1.3.4 及更早 EXE 无法打开升级后的 schema 14 库，不直接降级。** 首次验收建议使用独立测试资料目录。

Import 的新导入、版本更新、恢复及回退共用参数配置：未指定时继承旧值，空字符串明确清空。更新 Journal 保存旧参数，回退还原原值；提交中断后的继续不重复或丢失参数。旧 Journal 缺少新字段时按原来的无参数状态读取，既有工作目录和 loader 的兼容逻辑保持。更新后用户另改配置时，沿用原有配置变化检查，要求重新检查后再回退。

## Windows 手动验收

1. 下载与功能提交对应的 Actions EXE，先在独立可写测试目录运行。不要用新建的空 `data/` 覆盖正式资料。
2. 选择目标 `trainPJ.exe`，填写 `-dx11` 并保存。关闭、重开管理器，在详情中确认参数仍在，从游戏库启动。
3. 用 Windows 任务管理器的「详细信息 → 命令行」或本机只读进程查询，确认目标进程收到 `-dx11`；另核对详情临时启动使用未保存草稿但不修改保存值。
4. 清空参数并保存，再重开管理器启动，确认进程命令行不再包含 `-dx11`。
5. 补验含空格参数、错误引号提示、Import 新导入及更新参数继承 / 覆盖 / 清空，以及更新后回退还原。MTool、QSP 和文档模式不应收到该参数。

自动化只使用隔离临时目录、数据库、合成文件和编译出的无界面参数回显程序；Linux 核心检查不替代 Windows 原生测试与真实游戏验收。
