# 游戏库查重 & Match 2.0

在侧栏“游戏整理”选择“重复检查”，点击“查找重复”。这里只匹配 SQLite 已保存的游戏资料；“目录扫描”继续负责发现未入库文件夹，两者不会自动触发彼此。

结果按匹配程度排序，用紧凑双列对比两个游戏的名称、版本、引擎、目录及匹配理由。长名称最多两行，可悬停查看完整名称及路径；未知版本或引擎不显示。“高度疑似”表示名称或已确认别名等强证据；“需要确认”包括多语言标题、包描述及辅助资料的相近匹配。可分别打开现有游戏详情。

## 确认、排除与回收

默认显示“全部”，可切换“待确认 / 已确认 / 已排除”，数量随决定同步更新。“全部”中确认后卡片原地更新；在单独状态列表中，卡片立即移到对应分类。卡片只显示一个当前状态标题，不把匹配程度与处理状态混用。

点击“不是同一游戏”标记排除，可撤销排除。点击“确认重复”保存决定；随后点击要删除的游戏卡片，再点“删除选中游戏”。删除的一份用淡红底与回收标识，保留的一份用淡绿底与保留标识。未选择时不能删除，查看详情或打开目录不会改变选择。不操作就保留确认状态，可稍后在“已确认”继续处理，也可撤销确认。

UUID 组合以固定顺序存入 SQLite schema 11 的 `duplicate_reviews` 表；它由原 `duplicate_ignores` 迁移而来，原忽略关系保留为“已排除”。确认及排除共用一份关系存储，相同组合不会重复保存；游戏改名或版本更新不会重置关系。移除任一游戏会级联清理对应关系，清空游戏库也会清理。

选择保留一份、删除另一份后，复用游戏详情的删除确认框，完整显示待删除名称、安装路径及保留的一份。预检、共享路径保护、运行状态校验、Windows 回收站及数据库移除均使用现有流程。成功后点击“完成”刷新库及结果，所有涉及已删除 UUID 的组合消失；失败保留确认状态并展示原因及部分已回收内容。取消确认不删除。不会自动合并任何资料，不提供永久删除。

每份游戏显示当前启动方式（包括 MTool）和文件夹修改时间。修改时间只在展示结果时按需读取根目录属性，每个游戏去重查询，不遍历子目录；无法读取时显示 `-`，重新检查可刷新。它仅供人工参考，不参与匹配评分。

## 性能与边界

- 复用 Import 的名称索引和匹配规则，用索引候选执行两两匹配；不限制为 Import 的前五项。每个组合只评估一次。
- 库内检查只使用已有资料，不扫描目录、不读取项目身份文件或存档内容、不修改游戏或存档。Import 仍保留原有本地身份增强及自动关联规则。
- 续作、外传、DLC、章节等明确冲突在库内检查中保守排除；通用工具 / 包装名不能单独建立重复关系。不同已知引擎降为“需要确认”。
- Import 和库内查重共用对官中描述、短日文原名及附加英文别称的处理。主要标题相近且特色启动文件或独有外部存档路径一致时，可推荐缺少第一季标记或英文拼写不同的版本；新增的宽松推荐不自动关联，不放宽不同季数、续作或外传保护。
- 没有共同原名、已确认别名或有效辅助资料时，完全不同译名可能无法识别。资料变化后会提示重新检查。
- 检查在后台任务执行，可取消。取消不替换上次完整结果；待确认结果在应用会话内保留，确认及排除状态跨重启保存，重启后无需重新检查即可继续处理。旧匹配分数及理由不缓存，重新检查时更新。超过 80 组时复用虚拟列表。
- 自动化夹具覆盖 500、1000、2000 个游戏及取消，使用宽松的调试构建耗时上限；不等同于正式 EXE 或真实库的性能验收。

## 手动验收

1. 已有游戏时进入“游戏整理”默认看到重复检查，空库默认目录扫描；切换和打开其他页面不会自动启动任务。
2. 检查真实库，核对不同版本、已确认别名、多语言名称，以及续作 / 外传 / DLC；分别打开两边详情。
3. 分别在“全部”和“待确认”中确认，核对卡片去向、唯一状态标题和分类数量；切换页面及重启后继续处理，撤销确认和排除。
4. 用可丢弃的测试副本分别选择两边卡片删除：核对修改日期、MTool 标记和确认框完整路径，回收后确认保留目录、存档及资料未变化，相关组合消失；运行中、共用存档及删除失败应阻止或保留确认状态。
5. 两个 Tab 分别设置搜索、筛选并滚动，切换后核对保留；检查中取消，之前的完整结果保留。
6. 回归目录扫描入库、Import 新导入 / 版本更新、随包 MTool 整目录回收、存档迁移及原回退流程。

功能已实现并构建 Windows EXE，自动化结果见 [验证记录](validation.md)，真实游戏库和回收操作仍待手动验收；尚未创建新版 Release。数据库迁移只在新代码首次打开数据库时执行；开发测试使用独立临时数据库，不备份正式数据库。
