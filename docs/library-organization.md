# v1.3 游戏库整理（开发中，尚未发布）

目标为收藏、自定义标签和批量修改游玩状态。正式版本仍为 1.2.1；本功能随独立 PR 审核和验收，版本号在发布准备时统一更新。PR 的开发 EXE 已使用 schema 13，即使关于应用仍显示 1.2.1，也不能用正式 1.2.x EXE 打开升级后的库。

## 收藏

- 游戏库列表和卡片的星标即时保存；点击不会打开详情或启动游戏。
- 快捷筛选「收藏」可与搜索、引擎、启动方式、标签和游玩状态组合，排序继续使用原来的规则。
- 不自动置顶或根据启动次数生成「常玩」标记。

## 标签

- 游戏详情 → 基础信息中添加或选择已有标签，移除胶囊即可解除关联；沿用「保存资料」及未保存关闭保护。
- 输入名称后可按 Enter /「添加」，也可直接保存资料，同时提交输入框中的名称。未保存的新标签不会写入数据库。
- 标签须为 1–40 个字符，不能包含换行或控制字符；每个游戏最多 32 个标签。全半角、大小写及连续空白的等价名称共用同一标签，保留已有显示名称。
- 列表和卡片显示最多两个标签及 `+N`，悬停显示完整名称；详情显示全部关联。
- 筛选弹窗可选择标签；多个标签要求**同时满足**，再与其他条件取交集。「全部」会重置收藏、标签及原有分类筛选。
- 筛选 → 管理标签中可重命名或删除。重命名同步所有关联游戏；删除前明确确认，只删除标签及关联。游戏文件、资料和存档保持原样。没有关联游戏的标签仍可管理，不自动清理。

## 批量状态

1. 游戏库工具栏进入「批量选择」，逐项勾选或全选当前筛选结果。
2. 全选覆盖所有匹配游戏，包括虚拟列表 / 卡片中尚未滚动到的条目；栏内显示结果数和已选数。
3. 选择「未启动 / 正在玩 / 已通关」，点击「应用到所选」。一次数据库事务提交；任意条目不存在或写入失败时整体回滚，界面保留选择供重试。
4. 切换搜索、筛选或页面会清空选择；排序与列表 / 卡片切换保留 UUID 选择，结束选择清空。库刷新后剔除已经不在结果中的条目。

只修改游玩状态，不写启动历史、不刷新入库或运行时间，也不触发启动和文件操作。已有规则继续有效：成功启动会改为正在玩，已通关保留。

## 数据与兼容

schema 12 → 13 为游戏增加默认关闭的收藏字段，并建立标签及 UUID 关联表；没有历史回填、自动标签或自动别名。迁移在事务中执行，失败回滚。

收藏与标签随 UUID 保留，覆盖版本更新 / 回退、手动改名、目录重新关联及整库路径迁移；移除游戏级联删除关联，清空游戏库同时清空标签。旧调用未提供标签时保留现有标记；已删除标签不能由旧草稿自动重建。

旧版 1.2.x 无法打开 schema 13。不备份正式数据库、WAL、SHM 或导出可恢复记录；自动化验证全部使用隔离临时数据库、目录和合成存档。

## 验收

- [ ] Windows EXE：收藏 / 取消、组合筛选、重启后保留，点击星标不启动或打开详情。
- [ ] 标签：创建、复用、移除、保存 / 放弃、重命名、删除及筛选；确认未自动生成别名。
- [ ] 批量状态：列表与卡片、筛选后全选、超过一个视口、失败重试、状态改变后项目退出筛选结果。
- [ ] 窄窗口、长中日英名称、多标签、高 DPI、键盘焦点；星标不遮挡路径状态，按钮和卡片保持对齐。
- [ ] 更新 / 回退与路径迁移后分类保留；此前真实游戏读档和 Portable 验收项继续保留。

Linux 完整检查与 Windows 原生测试、严格桌面 Clippy、EXE 构建分别记录。CI 成功不代表上述实机界面和真实游戏验收已完成。
