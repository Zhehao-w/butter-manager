# 游戏状态、筛选和文件删除

当前适用于 v0.3.0。游戏状态、筛选和删除复用现有游戏库界面；版本替换及内部存档保留见 [v0.3 实施说明](v0.3-implementation.md)。

- schema 8 新增 `play_status`，已有启动时间的游戏初始化为 PLAYING，其余 UNPLAYED。COMPLETED 手动设置，成功启动不会覆盖。启动失败不记录状态。状态与成功启动记录在同一个事务保存。
- 游戏详情沿用保存与未保存提醒；启动配置未变时允许修改状态，即使游戏目录或启动文件已缺失。
- 游戏库列表在游戏名称旁提供启动按钮，复用详情的启动请求及状态更新；启动按钮不打开详情，处理期间阻止重复请求，缺失路径或未完整配置的游戏不可启动。上次运行与入库时间合并为一列上下显示，小窗口优先显示游戏名称和启动操作。详情的基础信息、启动配置在第一排，别名、存档位置在第二排，同排卡片等高。
- 游戏库支持状态、引擎、启动方式组合筛选；组内 OR、组间 AND，继续叠加搜索和需处理筛选。列表、卡片、详情显示状态及统一启动方式颜色。
- 筛选弹窗使用浅色选项卡片及官方 Lucide 图标，复选框、图标、文字有固定对齐位置。点击完成应用当前选择；取消、右上角关闭及 Esc 放弃本次修改。清空筛选只修改弹窗中的选择，仍需点击完成。底部操作区保持固定，选项随小窗口滚动。
- 游戏库、扫描和导入排序分别保存在 WebView 本机存储，选择时即保存；筛选和搜索只保留在当前会话。
- 游戏库列表/卡片视图也保存在本机，重新打开恢复上次选择。列表名称与状态文字采用一致的左边缘和固定间距。
- 启动窗口先隐藏，按鼠标所在屏幕的可用区域居中后显示；无法获取鼠标屏幕时退回主屏幕。尺寸按该屏幕的缩放比例计算，必要时收缩以留出任务栏与边距，不恢复历史坐标。
- 卡片视图固定高度为 288px，底部提供独立的直接启动按钮；名称按钮或卡片空白处打开详情。卡片高度与虚拟列表估算保持一致，缩短卡片不改变滚动机制。

## 删除

仅移除记录沿用原功能。新增文件删除必须经过单独弹窗确认；后台以一次性 token 保存预览，执行前重新检查实际目录和存档配置。操作期间复用现有任务锁，不强制关闭游戏。

删除游戏固定包含已关联的存档，不再提供保留选项或转存目录入口。游戏目录外的关联存档先移入回收站，目录内存档随整个游戏目录移入回收站；重复或嵌套的存档路径合并处理，不创建存档副本。没有配置的外部存档不猜测。保留存档的选择仅出现在导入替换流程：保留内部旧存档或使用新包存档，外部存档不操作；设置中没有全局保留存档选项。

系统/用户根目录、库根目录、管理器目录、公共工具目录、其他游戏重叠范围及共用存档范围会阻止删除。链接/联接点不递归处理，含这些结构的游戏须手动处理。支持相对路径、`<GAME>` 和可解析的环境变量；未知占位符、通配符不参与文件删除。

Windows 使用 IFileOperation，设置回收站、遇错停止和无关联文件操作的标志；进度回调拒绝未标记为回收站操作的删除。不使用 shell 删除命令或永久删除后备方案。参考 [微软操作标志文档](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)及 [PreDeleteItem](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-predeleteitem)。

文件删除与 SQLite 无法成为一个原子事务。每一步失败都保留库记录，结果列出已完成回收的目录或文件；不会自动撤销已完成的文件操作。再次处理需生成新预览。断电或应用被强制终止后，记录仍可能指向已回收的目录，可以通过目录检查和仅移除记录处理；已回收的游戏及存档仍可从回收站访问。

自动化文件操作使用独立临时夹具和可注入回收适配器；原生回调测试不触碰真实游戏，不依赖 GUI。实际 WebView 排版和真实游戏删除未经 GUI 自动化验证。正式库升级只核对记录数、完整性和旧列不可恢复摘要，不创建数据库副本或记录导出。
