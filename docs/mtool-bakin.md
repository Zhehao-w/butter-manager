# MTool 的 Bakin 专用启动（1.5.0）

RPG Developer Bakin 使用公共 MTool 的 `loaders/BakinLauncher.exe` 启动，普通游戏继续使用既有 injector / loader。策略按游戏保存；不需要为某个游戏修改「MTool」页的全局 injector。

## 识别与配置

分析组合检查 `data/bakinplayer.exe`、`data/bakinengine.dll`、`data/data.rbpack`。完整资源布局与唯一的根目录游戏 EXE 可识别 Bakin；多个 EXE 时，Windows 进一步读取 ProductName / FileDescription 的 `RPG Developer Bakin`、`BAKIN Game Launcher` 资源，帮助选择游戏启动器。只有产品名或单个资源文件不足以确认引擎；存在其他引擎冲突时继续要求人工确认。

`data/bakinplayer.exe` 属于内部播放器，不作为游戏启动文件推荐。已有游戏可通过「游戏整理 → 目录扫描」手动完成扫描，或使用游戏库的「扫描目录」入口：完整扫描发现 Bakin 后，会刷新未识别或非手动指定的引擎信息。

已使用 MTool 的 Bakin 游戏（包括已经识别引擎的旧记录）会从普通注入自动切换到 Bakin 专用策略，工作目录归一为游戏根目录。启动文件、MTool 目标、直接启动参数及未启用的 DLL 配置保留，不修改公共 injector。

直接启动 / 外部播放器不因引擎识别改成 MTool；原有下载包 MTool 标记补全规则继续有效，在同次扫描补全 MTool 时一并选择 Bakin 策略。明确手动指定的其他引擎、不完整 / 冲突结果及路径不匹配不覆盖；重复扫描不重复写入。若此前手动指定了其他引擎，在详情点击「分析游戏配置」，进入启动配置的分析结果，点击「采用此引擎」，然后「保存资料」；也可在基础信息直接选择 Bakin 并保存。

引擎选择与筛选共用支持列表，Bakin 在筛选弹窗中始终可选；游戏库快捷筛选仍按库中引擎数量和可用宽度展示，更多引擎通过筛选弹窗选择。Bakin 使用独立的浅暖色徽标。详情页重新分析后检查草稿并保存；Import 在「启动配置」使用同一策略选项，可手动选择「普通注入」或「Bakin 专用启动」。切换策略不修改公共 injector，也不会给游戏自动添加直接 EXE 启动参数。

Bakin 模式隐藏普通注入的位数 / DLL 选项，工作目录固定为游戏根目录。直接启动参数继续保留，但不传入 MTool 进程。详情临时启动使用当前草稿；游戏库使用已保存的配置。

## 执行与静态 BAT 证据

实际通过进程 API 顺序执行：

1. 公共 MTool 的 `loaders/BakinLauncher.exe`，只传当前游戏启动器的完整路径，工作目录为当前游戏目录。
2. 等待专用启动器成功退出，再启动公共 MTool runtime，参数为公共 MTool 根目录，工作目录仍为游戏目录。

不额外传入 mzHook DLL，不执行下载 BAT，不经过 cmd 或 PowerShell。专用启动器缺失、目标越界、启动失败或退出状态异常会报错，不静默改成普通注入；runtime 失败也保留已启动游戏的进程跟踪。沿用 Windows Job Object 对启动器及后代进程的保护，内部实际播放器仍计入文件操作保护；关闭管理器不终止游戏。

BAT 继续只作为静态证据，新增明确的 `BakinLauncher.exe <游戏启动器>`、随后 `start "" <runtime> <工具根目录>` 格式。启动器必须位于同一工具根目录的 `loaders/BakinLauncher.exe`；游戏路径支持 `%~dp0` 相对路径，绝对路径必须验证属于 BAT 所在的当前游戏目录且文件存在。旧绝对路径已经失效时不接受该证据。未知命令、动态展开、跳转、混合或重复启动配方继续拒绝。

分析能够确定游戏目标时优先使用分析结果；匹配该目标的 BAT 可补充启动策略证据，不替换目标。不能确定时才允许使用经过路径验证、无冲突的 BAT 配方回退。实际启动重新解析当前游戏路径及公共工具配置，不复制 BAT 中的旧工具根目录。Bakin 启动策略不决定随包工具是否清理；当前清理规则见 [随包 MTool 清理](import-mtool-cleanup.md)。

## 数据兼容与验收

1.5.0 使用 **schema 15** 的每游戏 `mtool_strategy` 字段；旧库自动迁移，已使用 schema 15 的开发构建无需再次迁移。旧数据库默认 `INJECT`；手动完整扫描可按上述条件为已识别的 Bakin + MTool 补齐专用策略。旧 Journal 缺少字段时继续采用普通注入，更新计划未显式覆盖则继承保存的策略。更新提交、中断恢复和版本回退保存 / 还原策略，撤回文件操作不依赖共享专用启动器存在。

**已发布的 1.4.0 及更早 EXE 无法打开迁移至 schema 15 的数据库，请勿直接降级。** 测试仅使用临时夹具，不备份或导出正式数据库。

Windows EXE 由 GitHub Actions 构建，正式交付为 Portable ZIP 与同名 `.zip.sha256`。实机验收：

1. 对已有 Bakin + MTool 普通注入记录完成一次手动目录扫描，确认自动切换为 Bakin 专用策略，重开管理器仍保留；直接启动与手动指定的其他引擎不改。使用完整公共 MTool，检查 `loaders/BakinLauncher.exe` 存在。对 Bakin 游戏分析，确认选中根目录游戏启动器、策略为「Bakin 专用启动」，保存后重开管理器。
2. 从游戏库启动，确认实际游戏及 MTool 正常打开；详情临时启动和 Import 后启动应保持一致。使用游戏自己的存档验证读档，Linux 测试不能替代此步骤。
3. 游戏运行时尝试目录重命名、导入更新或回收，确认文件操作保护生效；退出实际游戏及 runtime 后保护应释放。
4. 在隔离测试目录中验证缺少专用启动器时报错，不回退普通注入；普通游戏仍走原 injector / loader。更新后恢复及版本回退应恢复相应策略。
