# v0.1 收尾与后续实施计划（历史）

本文件保留 2026-10-06 的原始拆分方案，下面的“下一迭代”及旧版隔离方案不再适用。当前 0.3.0 使用内部存档覆盖、旧版回收站回退和轻量搬移，不长期保留旧游戏；以 [v0.3 实施说明](v0.3-implementation.md) 为准，后续工作见 [roadmap](roadmap.md)。

日期：2026-10-06。当时用户已确认批量、默认移动、已有游戏替换与存档保护放在 v0.3。v0.2.0 已实施批量新游戏导入；当时边界见 [v0.2-implementation.md](v0.2-implementation.md)。以下拆分为原始规划，不再表示待执行的下一迭代。

## v0.1 状态

原始 Library + Launcher 范围已实现：SQLite 迁移与 UUID、设置 / 原生目录选择、有限深度扫描、游戏库 / 详情、标题 / 版本 / 启动文件人工配置、别名 / 手填存档位置、直接启动、保守 BAT 解析、公共 MTool 配置 / 启动及打开目录。后续反馈要求的性能任务 / 取消、连续列表、引擎设置、运行时间、目录维护也已实现。

用户确认本机一次真实 MTool 启动成功，解除该配置的实际启动验证缺口；不会将它扩大为所有游戏或两种位数都已实测。当前没有已知功能 blocker。仍保留正常后续验证：更多样本、非 EXE 关联播放器、最低窗口尺寸视觉、长路径 / 权限环境及磁盘负载测量。未知编码或复杂 BAT 仍返回 unsupported，可使用手动公共 MTool 配置；不为兼容而执行 BAT。

## 历史规划：v0.2.1 + v0.2.2，只读分析与计划

1. 导入页用原生文件夹选择器选择一个已解压目录。可取消分析，展示建议名称、版本、引擎、启动文件、候选存档目录与自带工具线索；复用浅层扫描，不默认遍历大量资源。
2. 利用已有 UUID、canonical title、display title、别名和规范化名称生成候选。优先精确 / 别名匹配，模糊匹配只作低置信度建议；显示匹配依据和已有路径 / 版本，始终让用户选择“新游戏”或某个已有记录。版本是字符串，不把 beta / 日期 / 数字自动判定为更高版本。
3. 生成 Import Plan：新 / 已有 UUID、来源 / 目标路径、旧 / 新版本、启动方式与文件、需保留存档、公共 MTool、文件保留 / 移入 / 隔离分类、冲突及空间需求。允许修改建议值并重新检查。
4. 计划记录来源与目标检查信息；来源变动、Game Root 或相关库配置改变时提示过期，重新分析 / 确认。路径重叠、来源已在库内、目标已存在、链接、不可访问、多个匹配以及没有启动文件都应有清楚解释。
5. 本迭代不写入来源 / 目标游戏目录，不执行 Apply；只交付真实可复查的计划，不展示能点击却无法执行的导入按钮。

验收：Unicode / 空格 / 长名称、同名不同版本、多语言别名、冲突和空匹配可人工处理；取消保留已确认内容；分析和计划不更改正式库或游戏文件。

## v0.2.3：只导入新游戏

确认计划后才搬入新游戏。先在目标临时目录准备并验证，再正式登记；同盘移动与跨盘复制分别处理，跨盘复制验证完成前保留来源。操作有阶段进度、取消和持久操作日志，文件与数据库提交分步但可恢复，避免文件搬入成功却没有库记录。重启可继续 / 回退未完成操作。

不覆盖已存在目标，不混用目录关联和文件导入。磁盘空间不足、权限失败、文件变动、取消及异常退出需要夹具验证；已有游戏的新版本只能保留计划，等 v0.3 实现。

## v0.3：手动更新与存档保护

更新计划明确选中的旧游戏 UUID 和版本，沿用别名 / 入库时间 / 历史等资料。用户先确认存档路径与恢复方式；未知存档不猜测。区分游戏内部、外部 / 占位路径、引擎配置及可能不兼容的新旧存档，覆盖冲突要求明确决策。

流程：存档快照 → 暂存新版本 → 隔离旧版本 → 安装新版本 → 恢复已确认存档 → 验证启动文件与资料 → 提交并记更新历史。保留旧版本用于回退，不直接删除。磁盘不足、复制失败、程序占用、取消、崩溃及数据库提交失败均需恢复测试。清理隔离目录是之后单独确认的操作。

开发不备份正式数据库；存档快照与旧游戏隔离是更新产品功能，不是开发数据库备份。

## v0.4 / v0.5

先做完整 bundled MTool 的保守检测和可恢复清理计划，保留游戏资源 / 插件与未知内容；只在共享工具和游戏启动计划验证后切换，不运行随包 BAT。之后依据真实样本改善引擎 / 别名 / 存档识别、缓存失效与性能诊断，不做封面抓取、云同步、游玩时长或自动更新。
