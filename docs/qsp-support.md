# 本地 QSP 支持

当前适用于 v0.3.0，播放器和主文件配置仍使用下面的模型。QSP 已接入手动更新、内部存档保留和回收站回退，完整发行包保留；执行与恢复流程见 [v0.3 实施说明](v0.3-implementation.md)。下文的 schema 6 → 7 和 2026-10-07 验证数量是接入时的历史记录，当前 schema 为 9。

最初在 v0.2 接入识别、导入、编辑和启动，复用现有扫描、批量移动计划、游戏详情和存档路径配置，不新增 QSP 导航或设置页。2026-10-07 构建了该轮本地运行版，不创建数据库备份，不发布安装包。

## Model / schema

新增 `EXTERNAL_PLAYER` 启动方式。`main_executable` 复用为本地播放器 EXE，`working_directory` 复用为工作目录，默认 `.`。新增可选 `external_player` 配置：

```json
{
  "player_type": "QSP",
  "scope": "GAME_LOCAL",
  "game_file": "彼女の冒険.qsp"
}
```

EXE 和游戏文件均使用游戏根目录内的相对路径。`GLOBAL` 名称预留，当前校验与界面只接受 `GAME_LOCAL`。

Schema 6 → 7：增加一个 nullable JSON 文本列 `games.external_player`，同时扩展 `launch_type` CHECK。SQLite 事务重建 games 表以修改 CHECK，保留全部旧列；别名、存档路径、运行历史和设置原位保留。迁移前在事务外关闭外键，提交前检查关联完整性，随后重新启用外键。失败时回滚；不备份正式数据库。已有记录不会自动切换启动方式。

## Detection / recommendation

- 沿用浅层扫描预算与资源目录跳过规则；发现 `.qsp`（大小写不敏感）标记 QSP，不执行任何文件。
- 完整扫描会刷新已有记录的 QSP 引擎，保留手动引擎及原有启动配置。QSP 目录中的 MTool BAT 不会让其被自动改成 MTool 启动。
- 完整扫描范围内只有一个 `.qsp` 时自动建议主文件。多个文件返回全部候选，按根目录优先、game/start 名称优先排序，但不自动选中。未完整扫描时也不自动选主文件。
- 对已有 EXE 候选按 QSP / QuestNavigator / QuestPlayer 名称特征，以及 player / 播放器 / プレイヤー 特征排序。只在完整扫描且恰有一个带特征的候选时建议播放器。其他 EXE 仍可手选；多个疑似播放器不自动决定。
- 不读取 EXE ProductName/FileDescription，不递归枚举资源树来寻找播放器，不假定某个版本兼容所有游戏。
- QSP 版本取自目录或主游戏文件名，不取播放器 EXE 名。
- 名称或别名匹配成立后，“同为 QSP”可作为补充说明；相同引擎本身不会产生匹配。

## Import / UI

扫描入库、导入预览、游戏详情和已有目录关联共用 QSP 配置组件，沿用现有输入、浏览按钮与卡片样式。仅外部播放器配置显示 QSP Player / 主游戏文件；普通游戏不显示这些字段。

原生选择器分别限制 `.exe` 和 `.qsp`，选择结果再次由 Rust 校验扩展名和目录边界；也可手输相对路径或从建议列表选择。手选 `.qsp` 会转为本地播放器配置，不依赖文件关联。

旧库记录可点击“分析启动配置”后使用“使用 QSP 启动”，或在引擎下拉选择 QSP / 启动方式选择 QSP 外部播放器。配置只修改当前草稿，需“保存资料”后启动。引擎控件复用标准 select，选中后仍可重新选择；自定义引擎单独填写。

ETO 示例：播放器 `Qqsp-1.9.0-win64\Qqsp.exe`，主文件 `Girls Life 0.9.5.qsp`，工作目录 `.`。mod 目录中同样有 `.qsp`，因此必须手选主文件。

主游戏文件必须明确选择才能生成可执行的移动计划或扫描入库。播放器可留空，导入成功后显示未配置，详情中补选后即可按当前配置启动，无需先保存；顶栏“保存资料”用于保留配置供列表启动和下次打开使用。多个主文件不静默决定。未保存编辑关闭时仍弹出放弃确认。

批量移动和更新保留整个目录，包括 Quest Navigator、standalone_content、assets、CSS、JS、config、图片、声音和自带存档。不会删除播放器或转换为公共运行环境。扫描可建议实际存在的常规存档目录，用户可在详情手工修正；更新只迁移已配置的内部存档。

## Launch

Rust 构造 `Command::new(validated_player).arg(validated_qsp).current_dir(validated_cwd)` 并 spawn。程序、单一游戏文件参数和工作目录分别传递，支持空格、中文和日文；不手工拼接 shell，不启动下载 BAT，不双击 `.qsp`，不使用 Windows 文件关联。成功发送启动请求后沿用既有运行历史记录。

## Validation / limits

自动化测试覆盖单一 / 多个 QSP 文件、播放器推荐与未知 EXE、缺少播放器入库、多文件阻止移动、目录完整保留、相对配置保存 / 编辑 / 重开 / 关联、旧 schema 全列与关联记录保留、名称匹配边界、Unicode / 空格参数和 cwd、UI 选择与未保存 popup，以及普通游戏字段不变。夹具内不会实际运行播放器。

接入时的历史验证：86 Rust 测试、63 UI 测试、TypeScript、Vite、桌面本地构建、all-targets Clippy（deny warnings）。增加已有记录的 QSP 引擎刷新、ETO / mod / 包装层 Qqsp 候选、引擎重新选择、导入分类和双按钮确认测试。源码 diff 自查与 whitespace 检查已完成。最新检查见 [验证记录](validation.md)。

2026-10-07 本地运行版已覆盖并启动，进程正常响应、启动日志为空。正式库原位 schema 6 → 7，升级前 570 游戏 / 570 别名 / 0 存档路径 / 1 设置 / 2 运行历史；按全部旧列计算的摘要全部一致，quick_check 为 ok，外键检查无问题。只保存不可恢复摘要，没有数据库、WAL、SHM 副本或记录导出。

界面沿用内侧焦点描边、独立复选框尺寸和共享引擎控件。当前导入分类为“新的导入 / 待确认 / 导入记录”，切换保留本轮分析草稿；导入记录按游戏及日期展示。分析及计划提示在底部状态区显示，浮动错误通知在导入页避开操作区。执行确认保留取消 / 确认并右对齐。

深层或资源子目录中的 `.qsp` 可能不在默认扫描范围，需手选或单独深度分析。未知播放器名称需手选。尚未实测真实播放器 GUI 或所有定制发行版兼容性；需要额外参数的播放器暂未支持。旧 QSP 记录可在详情将启动方式改为 QSP / 外部播放器并配置主文件，既有记录不自动改写。Shared Player 留后续设计；本地 QSP 包的更新和内部存档保留已在 v0.3 实现，不转换存档格式。
