## 已交付 · 游戏库与 v0.3 本地更新

- [x] 列表 / 卡片启动、名称 / 别名 / 路径搜索、视图与排序记忆；直接 EXE、默认应用、共享 MTool 与本地 QSP 支持。
- [x] 扫描发现新游戏并检查已有目录与启动文件；人工选择入库，已有手动资料保留。

- [x] 更新选择保留内部旧存档或使用新包存档，计划预览后一次总确认；同版本来源副本可单独回收。
- [x] 同盘移动、跨盘单次复制及清单 / 大小核对；普通资源不做全量内容指纹或逐文件占用预检。
- [x] 更新按新包与确认的目标名称同步目录名、显示名、标准名、版本号及相关路径；保留原 UUID、别名、状态和运行历史。成功更新刷新入库时间，同一导入重试及版本回退不重复刷新。已有历史更新的名称与路径修复已执行。
- [x] 内部旧存档迁移到新版相同相对位置；外部存档在更新与回退中保持原位，保留必要的内部存档校验。
- [x] 中断继续 / 撤回、提交前恢复原位置、成功项保留；完成后旧版进入回收站并清理暂存。
- [x] 从仍存在于回收站的最近原旧版回退，将当前内部存档带回旧版；清空回收站后不能回退。
- [x] 导入记录按游戏和日期展示，支持跨批次搜索、详情、查看游戏及回退入口。
- [x] Portable 资料位于 EXE 旁的 `data/`；开发使用独立 `data-dev/`，不读取或迁移旧 AppData 库。

更新与恢复语义见 [v0.3 实施记录](v0.3-implementation.md)、[Portable 说明](portable.md)。历史记录中“保留旧名称 / 安装位置”的描述属于早期行为，当前以新版本名称同步规则为准。

后续界面调整以实际反馈为依据，不为填满空间增加模块，不扩大为全局重构。

## 已交付 · Save Editor Lite 首期

- [x] 游戏详情统一编辑入口、槽位选择、分类 / 搜索、修改草稿与批量保存、未保存确认；长字段列表虚拟滚动。
- [x] 标准 MV / MZ 简单变量、开关、金钱与物品数量编辑，角色只读；兼容旧版 MV JsonEx 数组包装，保留未知字段与引用元数据。
- [x] Ren’Py 普通存档 / persistent 受控解析与编辑、原签名状态、目标游戏本机密钥重签、外部文件临时授权与来源确认。
- [x] 字段类型展示，字典 / 列表 / 元组与已知 Revertable 容器的已有简单子字段编辑，None 明确类型初始化；容器折叠与子字段搜索。
- [x] 标准 `RevertableSet` 的字符串成员增删：仅开放结构明确的协议 2–5 样本，保留对象类型与引用定义；普通集合和未知自定义对象保持只读。
- [x] 文件 revision 检查、验证后的同目录临时替换；编辑 / 重签与导入 / 更新 / 回退互斥，不新增数据库表或持久备份。
- [x] 合成 Pickle 协议 0–5 独立往返验证，覆盖容器、引用与不可编辑边界；真实游戏 persistent 只读兼容探针通过。

《A Ninja’s Return v1.08 忍者归来》的 `gallery_unlocked` 已确认属于受支持的字符串 `RevertableSet`，读取与内存增删往返可行；未写回真实存档，也未完成游戏内显示验收。不根据字段名猜测含义，不提供一键全部解锁。范围与操作说明见 [存档编辑器说明](save-editor-lite.md)。

## 已实现 · v0.5 游戏库查重 & Match 2.0

当前源码和本地 EXE 已包含以下功能，真实游戏库与文件操作仍待统一手动验收。v0.4 / v0.5 是功能里程碑，当前配置版本仍为 0.3.1，未创建新版 Tag 或 Release。

- [x] 复用 Import 的 `MatchIndex`、名称匹配及辅助资料评分；库内匹配排除自身、每个 UUID 组合只显示一次，区分“高度疑似”和“需要确认”并展示原因。
- [x] 匹配显示名、标准名、别名、目录名与版本；利用已保存的特色启动文件和外部存档路径，保留中日英混合名称与汉化包处理。库内推荐对续作、外传、DLC 更保守，不改变 Import 的自动关联规则。
- [x] 只从当前 SQLite 读取资料，手动启动检查，可取消；不读取游戏内容、生成文件哈希或自动关联、合并、删除。
- [x] SQLite schema 11 将原忽略关系扩展为确认 / 排除状态，共用轻量 UUID 关系表，支持撤销，移除游戏时级联清理；不操作即可保留已确认状态，不保存匹配历史或额外缓存。
- [x] 紧凑双列游戏对比、状态数量及直接处理入口；复用现有删除预检、运行检查及回收站流程，二次确认删除哪一份、保留哪一份，失败保留确认状态。
- [x] 确认后通过游戏卡片选择删除对象，展示目录修改日期与 MTool 启动方式；Import 和查重复用短日文名、官中标记及项目资料支持的名称兼容规则，新推荐继续要求人工确认。
- [x] 原“扫描入库”更名为“游戏整理”，导航顺序为游戏库、导入、游戏整理、MTool、底部设置；内部包含重复检查与目录扫描，空库默认扫描，已有游戏默认查重。
- [x] 两个功能独立执行，保留筛选、结果与滚动位置；疑似组合可分别打开现有详情，较多结果使用现有虚拟列表。
- [x] 查重默认“全部”，提供待确认 / 已确认 / 已排除数量；状态筛选下操作立即转移分类，统一卡片状态标题，支持打开目录和明确的“移入回收站 / 保留”选择。
- [x] Import 默认勾选新增游戏，保留未确认与失效启动配置阻断；紧凑摘要始终可见，详细设置采用平行小 Tab，存档处理跟随关联选择。
- [x] 生成计划后项目从“新的导入”转入“待确认”，成功后进入“导入记录”；部分成功只移走完成项，返回调整恢复草稿，避免已计划或已完成游戏残留。
- [x] 最终验收前修复计划摘要的新目标文件夹、问题解决后的多余留白及标题栏 / 系统关闭的未保存保护；版本更新不再积累名称别名，已有手动与历史别名保留。
- [x] 增加组合去重、多语言、续作保护、忽略迁移 / 重启 / 撤销 / 删除、取消及 500 / 1000 / 2000 游戏性能回归测试；使用独立夹具。

边界：没有共同名称、已确认别名或可用辅助资料的不同译名可能无法推荐。标记差异较大的作品保守排除，人工修改资料后提示重新检查，不自动重新运行。未确认结果仅在本次应用会话保留，确认及排除关系跨重启保存。具体操作及验收见 [游戏库查重](library-duplicates.md)。

- [x] 成功刷新目录状态，失败显示原因；不更改存档关联、游戏资料或本地 `game/saves`，不增加数据库表或自动清理。
- [ ] 实机验收正常清理 / 取消、运行中手动清理、回收失败反馈，确认游戏目录存档和已有 AppData 关联保持原样。

- [x] 仅在一个 SQLite 事务中更新有效游戏的路径 / key、内部绝对存档及根目录设置；无效项跳过且保留原记录，数据库或目标变化需重新预览。名称、版本、别名、状态、时间与所有历史 / 查重关系保持。
- [x] 公共 MTool 位于旧根目录内时按原相对位置同步，保留相对程序配置；验证失败保持旧设置，有效游戏仍可迁移。不移动、删除、重命名文件或改写 Import Journal。

- [x] 复用现有 Windows CI 完整检查，保留 PR EXE artifact；未来 Release published 或显式手动发布到已有 Tag / Release 时上传已验证资产，不创建 Tag、Release 或自动改版。
- [ ] 验收新电脑上的整库迁移、共享 MTool / QSP 启动、失效项手动处理及干净 Windows 首次启动。当前版本仍为 0.3.1，本轮不执行正式发布。
