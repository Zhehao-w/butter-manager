# butter-manager Roadmap

更新：**2026-10-16** · 当前版本：**1.1.0**（正式资产以 Release 页面为准）。

本页区分正式交付与实机验收。1.1.0 在 1.0.0 基础上新增 ES3 / Naninovel 存档编辑；Release 提供 Portable ZIP 与 SHA256SUMS.txt，独立 EXE 继续通过 CI artifact 获取。v1.0.0 的独立 EXE 附件保留历史状态。当前流程以 [README](../README.md)和最新专项说明为准。

## 已实现 · v0.5 游戏库查重 & Match 2.0

- [x] 复用 Import 的 `MatchIndex`、名称匹配及辅助资料评分；库内匹配排除自身、每个 UUID 组合只显示一次，区分“高度疑似”和“需要确认”并展示原因。
- [x] 匹配显示名、标准名、别名、目录名与版本；利用已保存的特色启动文件和外部存档路径，保留中日英混合名称与汉化包处理。库内推荐对续作、外传、DLC 更保守，不改变 Import 的自动关联规则。
- [x] 只从当前 SQLite 读取资料，手动启动检查，可取消；不读取游戏内容、生成文件哈希或自动关联、合并、删除。
- [x] SQLite schema 11 将原忽略关系扩展为确认 / 排除状态，共用轻量 UUID 关系表，支持撤销，移除游戏时级联清理；不操作即可保留已确认状态，不保存匹配历史或额外缓存。
- [x] 紧凑双列游戏对比、状态数量及直接处理入口；复用现有删除预检、运行检查及回收站流程，二次确认删除哪一份、保留哪一份，失败保留确认状态。
- [x] 确认后通过游戏卡片选择删除对象，展示目录修改日期与 MTool 启动方式；Import 和查重复用短日文名、官中标记及项目资料支持的名称兼容规则，新推荐继续要求人工确认。
- [x] 原“扫描入库”更名为“游戏整理”，导航顺序为游戏库、导入、游戏整理、MTool、底部设置；内部包含重复检查与目录扫描，空库默认扫描，已有游戏默认查重。
- [x] 两个功能独立执行，保留筛选、结果与滚动位置；疑似组合可分别打开现有详情，较多结果使用现有虚拟列表。
- [x] 查重默认“全部”，提供待确认 / 已确认 / 已排除数量；状态筛选下操作立即转移分类，统一卡片状态标题，支持打开目录和明确的“移入回收站 / 保留”选择。
- [x] Import 默认勾选新增游戏，保留未确认与失效启动配置阻断；紧凑摘要始终可见，详细设置采用平行小 Tab，存档处理跟随关联选择。
- [x] 生成计划后项目从“新的导入”转入“待确认”，成功后进入“导入记录”；部分成功只移走完成项，返回调整恢复草稿，避免已计划或已完成游戏残留。
- [x] 最终验收前修复计划摘要的新目标文件夹、问题解决后的多余留白及标题栏 / 系统关闭的未保存保护；版本更新不再积累名称别名，已有手动与历史别名保留。

边界：没有共同名称、已确认别名或可用辅助资料的不同译名可能无法推荐。标记差异较大的作品保守排除，人工修改资料后提示重新检查，不自动重新运行。未确认结果仅在本次应用会话保留，确认及排除关系跨重启保存。具体操作及验收见 [游戏库查重](library-duplicates.md)。

- [x] 调研 QSP、TyranoScript、SugarCube、旧版 RPG Maker、Unity / Godot、KiriKiri / KAG 与 WOLF，区分可解码、可保真写回和可在游戏中读档。

- [x] **ES3：** `.es3` 明文 / GZip typed-entry，已知密码的标准 AES-128-CBC 容器（含先压缩再加密）；已有布尔、文本和明确整数 / 浮点类型可编辑，复杂对象与未知类型只读。
- [x] **Naninovel：** 明文 `.json` 与 raw DEFLATE `.nson`，标准 `CustomVariableManager` 本地 / 全局变量；新版类型化变量及旧版字符串映射。文件按独立槽位写回，不自动同步其他槽位。
