# butter-manager Roadmap

更新：**2026-10-22** · 当前版本：**1.5.0**（正式资产以 Release 页面为准）。

1.5.0 增加按游戏保存的 MTool Bakin 专用启动、已有游戏的引擎与策略扫描补全，统一紧凑筛选和标签交互。功能 PR #23 已合并到 main `6ad8e01`；最终功能提交 `8f178e1` 的 Linux / Windows 完整检查、桌面严格 Clippy 与 EXE 构建通过（39865597498），发布版本与 Tag 检查独立记录。

本版使用 **schema 15**，从 1.4.0 及更早版本首次升级时自动迁移；已使用 schema 15 的开发构建无需再次迁移。**1.4.0 及更早 EXE 无法打开升级后的库，不直接降级。** 规则与验收步骤见 [Bakin 说明](mtool-bakin.md)。

既有启动参数、ES3 / Naninovel 编辑、人工关联记忆、收藏 / 标签 / 批量操作及文件保护继续保留。Release 提供 Portable ZIP 与同名 `.zip.sha256`；独立 EXE 通过 CI artifact 获取。用户已确认 Bakin 专用启动正常，其他 Windows 实机、真实读档及分发验收继续保留，不以 CI 或发布状态代替。

1.0.0 汇总现有游戏库、导入更新、存档编辑、随包 MTool 清理、库内查重、Ren’Py AppData 手动清理及整库路径迁移。下文 v0.3.1、v0.4、v0.5、v0.6 保留为开发阶段名称，不代表分别发布过这些版本；历史交付见 [变更记录](../CHANGELOG.md)。

## 已交付 · 1.5.0 Bakin 与游戏库交互

- 组合资源布局及 Windows 产品元数据识别 Bakin，优先根目录启动器，排除内部播放器；手动扫描补齐未识别引擎，并为 Bakin + MTool 普通注入补齐专用策略，保留明确手动指定的其他引擎。
- 每游戏策略区分普通注入和 BakinLauncher，覆盖详情 / Import / 临时启动及更新、恢复和版本回退；专用启动不额外注入 DLL，沿用进程树与文件操作保护，不改全局 injector 或随包工具清理规则。
- 引擎选项、徽标与筛选补齐 Bakin；收藏采用统一选择卡，宽窗口采用紧凑四列引擎布局、收藏 / 状态同行；内容独立滚动，底部操作固定。
- 标签管理可从筛选及详情进入，只保留顶部关闭，返回原页面并保留草稿；详情已有标签直接选择、自然折行，重命名 / 删除同步标签草稿。

### 1.1.0 · 新增存档修改支持

编辑器在 MV / MZ 与受控 Ren’Py 基础上新增 Unity ES3 / Naninovel；不代表支持所有 Unity 游戏或旧版 RPG Maker。具体来源与投入见 [总体调研](save-format-research.md)及 [Unity 开源实现专项调研](unity-save-research.md)。

- [x] 调研 QSP、TyranoScript、SugarCube、旧版 RPG Maker、Unity / Godot、KiriKiri / KAG 与 WOLF，区分可解码、可保真写回和可在游戏中读档。
- [x] 对照 Unity 相关编辑器 / 解析库的实际源码、读写能力、许可证与运行依赖，区分 ES3、Naninovel、JSON、NRBF 与 PlayerPrefs。
- [x] **ES3：** `.es3` 明文 / GZip typed-entry，已知密码的标准 AES-128-CBC 容器（含先压缩再加密）；已有布尔、文本和明确整数 / 浮点类型可编辑，复杂对象与未知类型只读。
- [x] **Naninovel：** 明文 `.json` 与 raw DEFLATE `.nson`，标准 `CustomVariableManager` 本地 / 全局变量；新版类型化变量及旧版字符串映射。文件按独立槽位写回，不自动同步其他槽位。
- [x] 保留未知内容、类型及非目标字段；Naninovel 游戏自定义服务、脚本位置、场景、缩略图与回滚历史不开放编辑，不增加一键解锁。
- [x] 复用现有编辑入口、槽位选择、搜索、草稿和关闭确认。仅检查已关联目录及一层 `Saves`；不改变已保存路径、不增加启动扫描。
- [x] 合成夹具与独立 Node 编解码核对，覆盖无操作原字节保留、目标字段修改、其他槽位保留、密码 / 损坏 / 类型 / 数量限制、链接和文件变化保护；不使用真实附件作为测试资料。
- [x] 功能 PR #3 的 Linux / Windows 完整检查、EXE 交付与 CI 缓存优化验证通过，已随 1.1.0 发布；后续维护保留相同检查。
