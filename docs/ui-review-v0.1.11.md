# v0.1.11 UI 逻辑检查（2026-10-06）

检查依据：用户截图、组件和状态代码、前端交互测试。未使用 GUI 自动化，不把 DOM 测试当作实际字体、圆角或滚动帧率的视觉验证。

## 本轮已处理

| 问题 | 调整 |
| --- | --- |
| 侧栏与返回按钮、设置横向分类提供重复导航 | 删除所有“返回游戏库”、设置横向分类和库中的“查看上次扫描结果”，统一侧栏导航与高亮。MTool / 设置共用未保存草稿，离开前确认；关于仅展示应用信息和许可。 |
| 点击扫描页入口会立即开始磁盘任务 | 侧栏只打开页面。无结果时有说明，由“扫描目录”主动开始；已有结果提供“重新扫描”。 |
| 扫描仍需翻页，新增候选淹没在已登记条目中 | 连续虚拟滚动；默认未入库优先，同组按目录修改时间倒序。可按文件夹名、修改时间、入库状态排序，搜索名称、路径、引擎、启动文件、版本。 |
| 虚拟滚动移走项目后会丢失展开状态 | 将手动启动文件、版本、勾选与展开状态保存在页面级，按安装路径标识项目。返回原位置时仍可继续编辑。 |
| 搜索隐藏了已勾选项，用户不清楚批量入库范围 | 工具栏同时显示总勾选数与当前可见勾选数；搜索不丢弃选择，入库使用全部勾选。 |
| 入库完成后自动跳页 | 留在扫描页，更新已入库标记、库计数并移除已提交勾选。 |
| 已入库候选显示灰色编辑按钮和扫描建议版本，容易被当成库中版本 | 已入库条目仅展示保存的启动文件与版本，使用“已入库”统一术语；资料修改在游戏库详情完成。 |
| “补充引擎/版本”看起来像版本更新，实际只能补齐未知资料 | 删除游戏库入口。引擎和版本在详情手工设置；目录匹配与保留存档更新仍按后续手动导入设计。 |
| 关于页出现目录提示和保存设置按钮 | 关于页隐藏配置表单与保存按钮，标题、图标、说明对应应用信息。 |
| 页面切换提示仍称“关闭” | 页面使用“放弃并切换”，详情弹窗保留关闭语义。 |
| 扫描通知消失后难以确认是否完整扫描 | 扫描页底栏保留完成 / 取消 / 失败状态，失败原因可在诊断区查看。 |

修改时间取扫描根目录下每个游戏文件夹自身的 filesystem mtime，并非启动文件 mtime、递归最新时间或版本发布日期；读取一次目录 metadata，不遍历资源树。无时间的项目排在末尾。

## 当时提出的后续项（v0.1.12 已实现记录维护与文件检查）

- 库中缺少目录缺失状态与逐项移除记录入口。外部删除游戏后旧记录仍保留，点击启动才报告路径错误；应在后续增加轻量检查与仅删除记录的入口。
- 目录改名 / 移动后的新候选暂不能与旧记录手动关联。当前依据安装目录匹配；同目录仅改启动文件名不会变成新游戏，但需要手动修正启动路径。后续手动 Import / Matching 应处理迁移、已有记录和版本更新，避免遗留重复记录。
- MTool 配置可填写和浏览根目录，但缺少单独的可用性验证结果。现有启动会验证文件；独立验证入口应在真实 MTool 样本验证后完善。

这些项已按用户授权在 v0.1.12 处理，见 ui-review-v0.1.12.md；真实 MTool 兼容性仍需样本验证。目录关联不等于文件更新或存档复制，自动更新没有实现。
