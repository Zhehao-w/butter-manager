# v0.2.0 批量新游戏导入（历史）

以下记录当时的新游戏导入流程和完整内容校验规则，仅供历史及旧格式恢复记录参考。当前版本 0.3.0 已支持更新与存档保护；新操作采用同盘移动、跨盘单次复制与清单/大小校验，不做普通资源内容比对或逐个占用预检。当前使用流程见 [v0.3 实施说明](v0.3-implementation.md)。

用户确认范围：批量、默认移动，复用扫描分析。已有游戏替换、存档位置识别和保留存档更新集中到 v0.3。新游戏来源目录中的普通文件、存档和空目录全部保留，不清理随包工具。

## 使用流程

1. 点击“添加文件夹”，可多选单个游戏或包含多个游戏的文件夹。根目录有可用启动文件时保留整个目录；干净的合集展开为下级游戏。若同时存在外层配置、资源或其他目录，则确认“整个文件夹作为一个游戏 / 分别导入里面的游戏”，选择范围后才分析。分析复用设置中的扫描线程，默认 2，可取消。
2. 搜索、名称 / 修改时间排序和勾选；人工修改名称、目标文件夹、版本、引擎、启动文件和公共 MTool。非 EXE 使用共用原生选择器。
3. 名称 / 别名一致或去除明确版本后一致显示匹配依据；默认关联已有记录并取消勾选。可以明确改为新游戏或搜索人工关联。版本不自动比较，模糊识别留后续。
4. 生成只读移动计划，显示来源 / 目标、启动方式、版本、文件数、大小、同盘 / 跨盘和冲突；调整后重新生成。已有游戏关联只预览，不允许替换。
5. popup 确认移动后才执行。标题、搜索和底部操作固定，列表独立连续滚动，超过 50 项虚拟化；复用现有搜索 / 排序 / 浏览 / popup。

目录发现过滤点号开头项（例如 `.accelerate`）、Windows Hidden / System 属性、系统回收站和卷信息目录，且不进入链接目录。识别只读取目录与文件信息，不执行 EXE / BAT。已选游戏的完整移动机制继续保留随包资源和存档。继续添加文件夹时保留本轮已编辑的名称、版本、关联与勾选，不重置草稿。

自动识别有 20,000 目录项 / 5 秒预算；读取不完整时要求选择更具体的文件夹，避免将部分识别结果直接当成完整合集。新逻辑由独立临时夹具验证，包含 Windows 真实 Hidden / System 属性、点号项、QSP 本地播放器、包装层范围确认及追加目录的草稿保留。

## 移动与登记

计划遍历所选游戏目录的普通文件清单、大小和修改时间；初次分析仍为有限深度。拒绝链接 / reparse point、特殊文件、重复或互相包含的来源、重复目标、已登记来源及存在的目标。保护应用数据、应用程序及公共 MTool。操作前复查设置、清单和目录对象身份，路径相同但目录被替换也会失效。

每项在 GameRoot 内使用独占 `.butter-import-<operation>-<index>` 暂存目录和 owner 标记，扫描排除暂存目录。Windows 目录移动不覆盖目标：

- 同盘：来源 → 暂存 → 正式目录 → 登记。
- 跨盘：复制 → 文件清单和完整内容比较 → 正式目录 → 登记 → 清理来源。提前检查空间，保留文件修改时间。
- 清理来源前逐文件再次比较。Windows 持有禁止改写 / 替换的来源文件句柄，通过该句柄删除已验证对象；新增或修改的内容停止清理。
- 每项 UUID 在计划中预留；重试只能复用该 UUID，不能接受其他记录抢占的目标。成功登记后取消不撤销已成功游戏。
- 文件传输逐个执行，减少磁盘争用。复制和校验按块响应取消；同步系统调用仍可能需要等待。

## 中断与恢复

本地 imports 目录只保存本次操作记录。不可变清单只写一次，检查点只写小型状态；成功或撤回后释放清单。不复制数据库、WAL、SHM，也不导出旧库记录。

重启导入页可选择未完成操作，popup 确认继续或撤回。未登记的同盘移动可返回未被占用的来源位置；跨盘暂存只有归属和内容可验证时才撤回。内容或身份异常时保留文件并报告，不丢弃异常。

已登记游戏保留。选择撤回时，跨盘剩余来源也保留并结束清理，以保护已经运行后变化的内容。成功项继续时不重复导入。失败但尚未进行文件操作的计划可返回调整。有未完成文件操作时，阻止新导入、相关设置修改、移除记录和清空数据库。

## 验证与边界

独立临时夹具覆盖批量 Unicode / 包装目录 / HTML、存档和空目录、只读计划、来源变化、目标冲突、已登记来源、库目录替换、取消继续、移动 / 发布 / 登记后恢复、部分复制、陌生内容保护和撤回保留新存档。实际 C → E 临时夹具验证跨盘复制、内容比较和移除来源。

没有用真实游戏做移动测试。原生多选选择器与 WebView 的视觉 / 焦点没有用 GUI 自动化验收；所有长路径、锁文件、权限和磁盘故障组合也未实测，失败保留文件并报告。

以上为 v0.2 的边界。当前 v0.3 已支持手动替换及内部存档保留，仍不包含压缩包解压、自动下载更新或 bundled Tool 清理。
