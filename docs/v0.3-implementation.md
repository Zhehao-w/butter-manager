## 匹配与确认

按目录名、名称和别名推荐已有游戏，去掉明确版本号后再匹配；目录名仍可匹配用户改过显示名称的游戏。保留续作编号，不比较新旧游戏文件内容，不比较版本字符串大小。推荐不自动执行替换，用户可以手动关联其他游戏，或明确按新游戏导入。

匹配另支持全半角、标点和词段顺序归一化；在推荐层去除 `V89`、`V88.GG` 等版本标记、点分发行日期及少量包描述（Extended / electron / GG）。完整英文名称相同且足够明确时，可在中文译名不同的情况下推荐同一个游戏。短缩写或相同引擎不足以建立匹配，普通续作编号仍保留。

新增归一化结果仅推荐，不自动关联；存在多个匹配时也必须手工选择。推荐旁可直接关联，或明确选择“改为新游戏”；手工关联弹窗优先显示推荐结果。唯一的完整名称或原版本归一化匹配沿用自动关联，但不自动勾选执行。

关联推荐统一在卡片左侧展示：未确认采用浅橙提示区域，按钮显示关联目标名称一次，旁边显示弱关联/名称匹配及具体理由；确认后改为浅蓝已关联状态。手动关联也进入同一展示区域，说明手动选择理由。手动关联、改为新游戏与同版本副本删除集中靠左，不再在右侧或底部重复目标名称。交互逻辑不变，导入页 17 项回归及 TypeScript / Vite 构建通过。

完整中文或日文名称相同（至少四个字符），且仅其中一份附有英文名时，也加入弱推荐，例如“希尔丝大冒险”与“希尔丝大冒险 The Adventures of HILLS”。不使用中文名称片段匹配，编号不一致或两份英文名不同仍不由此规则建立关联。

确认关联且两个明确版本号相同后，导入卡片显示“删除导入副本…”。允许 `v1.1.4` 与 `1.1.4` 等前缀差异，不将 Unknown、空值或不同分段版本视为相同。用户仍可选择正常替换；同版本不代表内容相同，绝不自动删除。删除预览列出来源与保留的库内目录，确认后仅将来源目录（含内部存档）送入回收站，不移除或修改库记录，不操作外部存档。

副本删除使用独立内存令牌，来源限定在已完成的导入分析结果，执行时重新核对来源目录身份、关联版本及删除范围。复用现有目录/共享存档/文件占用保护，额外禁止删除游戏库和公共工具目录内的来源；当前任务或未完成导入文件操作会阻止删除。没有永久删除兜底或新数据库字段。取消确认不操作文件，成功后从当前导入列表移除副本。

关联与副本删除验证：134 项后端测试、17 项导入页测试通过；严格 Clippy、格式检查、TypeScript / Vite 及本地正式构建通过。回收测试只使用临时目录和模拟回收，不删除真实游戏；Windows 原生回收站集成测试仍默认跳过。

“生成导入与更新计划”仅在关联待确认时显示数量与原因。更新卡片用互斥选项选择“保留旧存档”（默认）或“使用新包存档”，无需额外勾选范围确认。生成计划提交所选存档处理方式，预览后仅保留执行前的一次总确认。

更新保留原 UUID、安装位置、名称、别名、入库时间、游玩状态、存档路径和运行历史。使用用户确认的新版本、引擎及启动配置，支持 Direct、本地 QSP 和公共 MTool。整个 QSP 本地发行包保留。

## 存档

范围来自已配置路径，在卡片和计划预览中展示。选择“保留旧存档”时，只复制游戏目录内存档，覆盖到新版本相同的相对位置。AppData 等外部存档完全不操作。选择“使用新包存档”时，旧存档随旧版本进入回收站。存档格式转换不在本轮范围。

内部存档保留必要的复制和内容校验。新包原有的同路径存档临时移开，未提交操作撤回时恢复这些原始存档；临时文件完成后全部清理。管理器文件不写进游戏或存档目录。

## 轻量搬移

1. 检查来源和目标目录身份、路径重叠、链接、目标冲突、运行进程与所需空间。跨盘执行前读取最新目录元数据作为复制清单。
2. 临时保留内部存档。同盘将整个新版本移动到本次暂存目录；跨盘只复制一份新版本，检查复制的相对路径、类型、数量和大小。
3. 暂时移开旧目录，新版本就位，把内部存档覆盖到原相对位置。
4. 检查配置中的启动文件及存档操作完成，原游戏记录与版本历史在同一事务中提交。
5. 跨盘提交后清理来源。删除来源前检查文件仍属于记录的来源，目标或临时存档归档中的副本大小正确；新增或修改的来源保留并报告未完成。
6. 旧版本移入 Windows 回收站，清理明确属于本次操作的临时文件。

新操作不计算整包内容指纹，不读取普通游戏文件做字节比对，不保留第二份完整 package。同盘主要额外空间为内部存档的快照与恢复副本；跨盘另需一份新版本的容量。文件清单用于复制完成检查和明确清理范围，不判断游戏内容是否正确。

新格式导入与更新不再逐个打开新旧游戏资源检查占用，只检查运行进程；目录切换、提交、回收与失败恢复/撤回同样使用进程检查。进程检查支持取消，进程路径每次枚举只解析一次。存档复制时仍保留必要的占用与内容校验、目录身份和恢复检查。实际文件操作失败则停止并保留恢复记录，外部存档不遍历。旧格式操作的后续检查、版本回退和独立删除继续使用原规则。

目录切换和数据库提交沿用原恢复检查点。提交前失败恢复旧版原路径，新版本保留在暂存中，可继续或撤回；同盘撤回将来源目录及其原始存档放回下载位置。提交后只继续未完成的来源清理、回收和暂存清理。清理清单生成前也必须根据已记录的包路径及存档快照核对范围，未知文件保留，不能直接把当前暂存目录全体内容视为可删除内容。

## 回收站回退

只恢复系统回收站中的原旧版本，按最近更新开始回退。回收站已清空或项目被手动恢复，无法回退。

新操作直接使用取回的旧目录，不再复制一份完整旧游戏。临时保留当前内部存档，覆盖到旧版相同位置，提交原配置与回退历史，再把当前版本移入回收站并清理临时存档。外部存档不操作。回退切换前撤回会恢复旧版原存档并把取出的目录送回回收站；切换后的中断通过继续操作完成。

已有旧格式记录保留原恢复规则，包括原来的校验和暂存结构。缺少新字段的记录不会被擅自转为轻量流程，避免已有中断操作无法继续。

## 导入与更新进度

导入页底部使用同一套整体进度，显示百分比、已处理游戏数、当前游戏和文件、当前传输字节、速度及预计传输剩余时间。

整体进度按游戏大小与处理阶段加权，同一任务跨文件、阶段和游戏不会倒退。实际传输字节单独显示，不将整体加权值当作已复制字节。速度由当前传输采样，非传输阶段、长时间没有传输更新或任务结束后隐藏速度和时间估计。剩余时间是估计，不承诺磁盘写入或回收站操作的精确耗时。继续任务会保留已完成游戏的进度，当前未完成项重新估算。

准备、运行进程检查与复制尚未开始时，通过任务的 indeterminate 状态显示连续滑动条并隐藏百分比，不因已知整体容量而停在 0%。实际传输或目录切换后显示阶段加权百分比；不会通过虚构数值推动进度。

任务创建时立即标明运行状态检查及游戏数量，避免检查期间停留在“准备 · 0/0”。分析状态栏固定预留第二行提醒空间，确认操作不再使第一行跳动。计划卡保留来源、目标、版本变化、存档选项与回收站说明各一次，移除重复的关联路径和保留字段描述。

文件夹选择独立于任务状态，打开或取消选择不会触发进度条，也不清除已有提示。选定目录开始识别后才显示任务进度。导入、扫描横幅和任务面板统一使用 8px 圆角浅蓝轨道，未知总量通过 CSS 连续滑动，实际进度通过 transform 平滑过渡，不提高任务轮询频率或虚构进度；遵循系统减少动态效果设置。此次前端回归 18 项通过，TypeScript / Vite 构建通过。

## 数据与验证

扫描与目录检查使用同一悬浮横幅，不占主列表布局空间。完成或取消后停留 5 秒，悬停及聚焦暂停倒计时；失败保留到手动关闭。退出时先在完整高度下渐隐 300ms，再收起位置 300ms，避免内容被裁掉和其他横幅突然跳动；手动关闭使用相同动画，遵循系统减少动态效果设置。

“已导入”改为“导入记录”：按游戏展开全部成功导入/更新与已回退条目，包含未完成或已撤回批次中保留的成功项。按本地日期分组、最新在前，移除已完成批次的长按钮选择器；搜索覆盖所有记录的名称、版本及路径。列表只展示游戏名、结果与时间，右侧提供查看游戏和详情；来源、目标、文件信息、启动配置、存档处理及回退入口移入详情。游戏不在库中时停用查看；回退沿用版本、回收站和恢复记录保护。

新条目首次完成时在既有操作记录中保存完成时间，重启与回退不改写该时间。旧条目只读使用记录文件修改时间并注明来源，不迁移或重写历史文件，不改数据库 schema。导入历史长列表沿用稳定虚拟滚动。

数据库 schema 仍为 9，不新增 migration。新字段只扩展操作日志和任务进度。开发与构建不备份正式数据库、WAL、SHM，不导出可恢复记录。

隔离测试覆盖：同盘目录身份保留；C/E 两盘单次复制、提交后来源清理和撤回；内部存档覆盖与原始下载存档恢复；外部存档不访问；普通游戏内容变化允许继续、存档变化需重新确认；首次及部分暂存清理拒绝未知文件；新旧记录全部更新/回退检查点重启恢复；整体进度不倒退、速度及时间估计及时失效；现有 QSP、MTool、删除和数据库迁移回归。

没有对真实游戏执行更新、删除、移动或回退；没有使用 GUI 自动化。

删除了依赖整目录资源占用预检查的导入测试，以及原完整预检查回调/遍历断言；现有运行进程、存档占用、删除和恢复测试保留。准备/传输进度验证合并在现有进度与取消测试中，不另加重复测试。未重复执行用户的真实更新。
